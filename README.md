# 指标口径与分析实验平台

面向业务指标定义、口径管理、聚合查询、分群分析、A/B实验设计、分析方案管理与数据服务发布的数据分析工程平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
- 跨模块写操作走 `store.transaction()`：进入时对全库加锁并保存快照，异常即整体回滚，
  保证「报表产物登记 + 数据服务发布」要么一起成功、要么两侧同时退回。

## 报表产物到服务版本的登记链路

报表数据服务的交付边界：报表任务、产物与返回字段必须按同一排期版本交付。

1. 报表任务执行「确认排期」后，在同一事务内登记一条**不可变**报表产物，记录
   数据日期偏移、实际数据日期（排期日期 − 偏移天数）、包含指标、返回字段与产物摘要，
   并按（数据日期, 指标集合）生成结果指纹。
2. 数据服务「发布服务」时必须携带产物编号 `artifact_code`：仅「已登记」产物可绑定；
   发布时冻结返回字段、数据日期与产物摘要快照。数据日期偏移或指标集合变化只能通过
   新排期产物 + 新服务版本交付，旧版本可追溯但不会被自动改写。
3. 幂等：同指纹的重复排期复用原产物、不生成新版本；同产物的重复发布直接复用，
   失败重试只补充缺失版本，不为同一结果创建重复服务。
4. 失败/中断排期登记带原因的异常产物（`生成失败`/`已中断`），任务保持评审态并标记
   异常，异常产物不能发布，异常排期不会显示成已发布服务。
5. 追溯：`GET /api/delivery/{id}/trace` 从服务返回字段追到报表任务、数据日期、
   产物摘要与审计记录；`/api/audit-logs` 同步记录每次发布版本与回滚。
6. 示例：REPO-0003 在 2026-10-12 排期生成含三项指标的产物 ARTI-0001，DELI-0003
   绑定该产物发布，数据日期为 2026-10-12，返回字段不会指向 10 月 11 日。
